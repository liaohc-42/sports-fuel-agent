# 🔥 练完吃啥 · 运动 × 饮食智能体

> 首届「软工菁英杯」技术创新应用大赛参赛作品 · 主题词：**运动**
> 面向**中山大学**学生的运动饮食智能体：**练完吃啥**（食堂运动餐推荐官）+ **体测急救站**（14 天体测提分教练）

纯**原生 HTML / CSS / JavaScript** 前端 + **Node.js (Express)** 后端，前端一键部署到 **GitHub Pages**，后端可部署到 **Vercel**。**无需后端、无需联网、无需付费**即可完整演示（内置本地规则引擎兜底）。

> **2026-11-04 重构**：产品升级为「练 + 吃 + 教练 + 场馆」四线，融合了同学方案的**积分雷达**与**场馆人流**；UI 改为「纸质票据 + 硬阴影」色系（米白 / 砖红 / 深绿 / 墨）。

## 🧭 功能总览

### 方案 A：练完吃啥（运动餐推荐官）—— 主项目

> 深绿卡片式 UI（参考概念图）：左侧「定目标 → 今天练了什么 → 今天吃什么 → 这顿的约束」，右侧「这顿吃什么：3 套搭配 + 为什么这么配」。

- **配餐**
  1. 目标三选一：**减脂 / 增肌 / 维持**（每项目标带一句说明）
  2. 运动类型：**跑步 / 徒步 / 游泳 / 力量 / 球类 / 休息**；时长 30/45/60/90 分钟；强度 轻松/正常/累（附参考说明）
  3. **数据源可切换**：默认「🌐 通用菜品库」（网上常见菜品数据），可切「🏫 中山大学食堂」用真实五校区菜单
  4. **菜单图片上传**：拍照/上传菜单 → OCR 自动识别菜品 → 一键加入
  5. **这顿的约束**：预算（10/15/20/不限）、路上时间（10/15/25/不赶时间）、餐次（午餐/晚餐/加餐）、**不吃的东西**（辣/花生/海鲜/蛋/奶/豆制品/麸质 + 猪/牛/羊/鸡肉）、体重、训练结束时间
  6. **一键出 2–3 套**：按蛋白优先 / 性价比 / 赶时间 / 均衡 4 条策略生成并去重，每套给出菜品、蛋白·碳水·千卡·价格、排队/全程时间、**蛋白覆盖率**、**为什么这么配**，支持「换一换」「就吃这个」
  7. **跑步测速**：输入距离+用时 → 配速 / 速度 / 消耗
- **记录**
  8. 按实际就餐**增删菜品**，给出未来 1–2 餐建议
  9. 近一月**饮食花销统计** + 设定月预算 → 省钱建议
  10. **最近运动**：本周/本月/今年 直方图 + 调整建议
- **原理与数据**
  11. 列出 AI 参考**文献**（《中国居民膳食指南(2022)》等）
  12. **智能健身教练**（Agent），API Key 只配置在**后端环境变量**

### 方案 B：体测急救站（《国家学生体质健康标准》全项目）—— 加分副项目

- **全项目评分**：BMI、肺活量、50米跑、坐位体前屈、立定跳远、引体向上/仰卧起坐、1000/800 米，逐项算分 + 加权总分（评分表内置，按年级自动切换「大一/大二」「大三/大四」两组、透明可查）
- **提分性价比**：如"引体 3→5 比 1000 米提 10 秒划算"
- **引体向上 / 仰卧起坐 专项训练计划**：4 周递进动作库（退让引体、弹力带辅助、澳洲引体、悬垂；卷腹、平板、俄罗斯转体等），含组数次数
- **7 天计划** + **打卡调载**（太累/疼痛/没时间自动降载换项，膝盖疼 → 深蹲换臀桥）
- **配速器**：目标成绩 → 每 200/400 米分段 → Web Audio 叮声报时，不依赖 GPS，操场跑步机都能用

### 方案 C：积分雷达（校园体育积分机会）

- 13 条预置机会：参赛即得 / 打卡累积 / 课程训练 / 服务组织 / 院系日常 + 5 条社团·民间（明确标注不计分）
- 分类 chips + 状态分段 + 关键词搜索，三者叠加；未结束按截止日升序、已结束沉底
- 详情页：AI 一句话摘要（失败有本地 fallback）、我想去 / 找搭子 / 组队缺人、讨论区、运动攻略评分
- 票根章分值样式；个人积分进度（本机记录，标注非官方认定）

### 方案 D：场馆与人流（去之前看一眼）

- 五校区 22 个场馆，自绘 SVG 示意图（不用地图 SDK、不涉及授权）
- **两级兜底判定**：① 近 2 小时上报 >60% 优先；② 无数据按历史规律表（20:40 下课、19:00–21:30 室内、工作日白天、周一闭馆…）；③ 默认「适中，欢迎上报」
- 点「人多 / 适中 / 人少」即时生效；人多时自动给替代场馆建议

## 🔑 大模型配置 ⚠️ 醒目入口（三种后端任选其一，Key 只在后端）

> **安全原则：Key 只放后端环境变量，前端不保存任何密钥。** 都未配置时自动使用本地规则引擎（离线、免费、稳定）。
>
> 支持三种后端：**GLM（智谱）** / **DeepSeek** / **Ollama（本地）**。大模型只做「解释、鼓励、问答」，输出经过 **JSON Schema + 规则校验**，失败自动回退模板。

**第 1 步：在 `backend/.env` 里填（复制 `.env.example` 为 `.env`）**

```env
# 方案一：智谱 GLM-4-Flash（免费）
GLM_API_KEY=你的智谱Key
GLM_MODEL=glm-4-flash

# 方案二：DeepSeek（Key 形如 sk-xxx）
DEEPSEEK_API_KEY=你的DeepSeekKey
DEEPSEEK_MODEL=deepseek-flash

# 方案三：Ollama 本地大模型（不联网、不花钱）
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=qwen2.5
```

> 三种都填时，用 `PROVIDER=glm|deepseek|ollama` 指定用哪个。

**第 2 步：启动后端**

```bash
cd backend
npm install
npm start        # http://localhost:3000   （会打印 provider = deepseek / glm / ollama）
```

**第 3 步：让前端指向后端**

编辑 `frontend/js/api.js` 第 1 段，改成后端地址（本地就填 `http://localhost:3000`）：
```js
var API_BASES = [
  'http://localhost:3000',                          // 本机后端优先
  'https://sports-fuel-agent-backend.vercel.app',   // 公网兜底
];
```

**如何确认生效**：浏览器打开 `http://localhost:3000/api/health`，`provider` 显示 `deepseek`/`glm`/`ollama` 即成功；页面右上角会显示「已连接 Agent」。

**未配置任何 Key 时**：后端 `/api/health` 返回 `agent:false`，前端自动降级为**本地规则引擎**——免费、无需联网、答辩现场最稳妥。

**🔒 安全提醒**：`.env` 已被 `.gitignore` 忽略，不会上传。答辩结束请立刻到对应平台删除 Key（用完即删，本项目的降级机制保证删了也不影响演示）。

> ⚠️ 国内网络提示：`*.vercel.app` 可能被墙。**最稳的是本地跑后端 + Ollama**，完全不走公网。

## ☁️ 部署

### 方式 0：一键部署（无需本机安装 git）★ 推荐

仓库里已备好脚本，只要一个 Token 就能自动「建仓库 → 传代码 → 开 Pages」：

```powershell
$env:GITHUB_TOKEN="你的token"     # 勾选 repo + workflow 权限
$env:REPO_NAME="sports-fuel-agent"
node scripts/deploy_github.js
```

脚本会打印最终访问地址 `https://<用户名>.github.io/sports-fuel-agent/`。

**如何获取 GitHub Token（约 2 分钟）：**

1. 登录 GitHub → 右上角头像 → **Settings**。
2. 左侧最底部 → **Developer settings** → **Personal access tokens** → **Tokens (classic)**。
3. **Generate new token (classic)**，勾选权限：**`repo`**（整个打勾）+ **`workflow`**。
4. 有效期选最短（如 7 天），生成后**立刻复制**（只显示一次）。
5. 用完即删：答辩后回到同一页面 **Delete** 即可。

> ⚠️ Token 等同账号密码，请勿粘贴到任何会公开的地方（本项目 `.gitignore` 已忽略 `.env`，脚本只从环境变量读取）。

### 前端 → GitHub Pages（自动，手动方式）

1. 新建 GitHub 仓库，把本项目推上去（`git push`）。
2. 仓库 **Settings → Pages**，Source 选 **GitHub Actions**。
3. 每次 push 到 `main`，`.github/workflows/deploy.yml` 自动部署 `frontend/`。
4. 页面地址在 Actions 运行完成后显示（`https://<用户名>.github.io/<仓库名>/`）。

### 前端 → GitHub Pages（浏览器上传，无需任何工具/无需 VPN 外的命令行）

1. 浏览器打开 github.com 新建空仓库（勾选 Add a README 可跳过）。
2. 仓库页点 **Add file → Upload files**，把整个 `sports-fuel-agent` 文件夹（或 `练完吃啥-项目源码.zip` 解压后的内容）**拖进去**。
3. 上传后点 **Settings → Pages → Source 选 GitHub Actions**。
4. 打开 **Actions** 标签，手动运行一次 `Deploy to GitHub Pages` 工作流。
5. 完成后得到 `https://<用户名>.github.io/<仓库名>/`。

> 注意：`frontend/` 目录是站点根目录，上传时请保留原始目录结构（不要只传 index.html 一个文件）。

### 后端 → Vercel（可选）

1. 把仓库导入 Vercel（或单独导入 `backend/` 目录作为 Root Directory）。
2. 环境变量加 `GLM_API_KEY`。
3. 部署完成得到 `https://xxx.vercel.app`，把它加到 `frontend/js/api.js` 的 `API_BASES` 数组里（放第一位最优先）。

> 也支持 Cloudflare Worker：`api/agent.js` 里的 `callGLM` 是标准 fetch，可平移到 Worker 的 `fetch` handler（见 `docs/完善路线.md`）。

## 🧱 技术架构

```
浏览器(GitHub Pages 静态)               后端(Express/Vercel)
┌──────────────────────┐      ┌──────────────────────┐
│ 原生 HTML/CSS/JS      │      │ POST /api/agent       │
│  · 配餐/记录/体测 UI   │ ───▶ │  · 组装提示词          │
│  · 本地规则引擎(离线兜底)│      │  · 调用 GLM-4-Flash    │──▶ 智谱API
│  · 营养库/MET库/食堂数据 │      │  · 隐藏 API Key        │
└──────────────────────┘      └──────────────────────┘
        ▲ 后端不可达/无Key时，自动用本地引擎，功能不降级
```

- **算分/算热量不用大模型**：体测评分表、MET 公式、营养库都是本地确定性计算，**大模型只做"解释、点评、问答"**，避免 LLM 算错或幻觉。
- **数据可追溯**：食堂数据来自《中山大学食堂菜单价格明细表》，每条标注出处；营养数据标注"库/估算值"。
