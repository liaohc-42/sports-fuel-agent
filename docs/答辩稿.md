## 0. 开场（30 秒）

各位评委老师好，我们的主题词只有两个字——**运动**。

很多队伍会把「运动」做成一个健身 App。我们换了个角度：**大学生运动前后，真正要做的两个决定是什么？**

- 练完这一顿，在食堂怎么吃；
- 这学期，去哪儿运动、什么时候去、体测算什么。

所以我们做了一个「运动 × 饮食 × 校园」的智能体：**「练完吃啥」负责吃，「中大通关 · 南校运动地图」负责练**。

一句话：**运动消耗的，吃回来；校园里的运动机会，帮你找出来。**

---

## 1. 痛点与选题（45 秒）

三个真实场景，都是我们身边每天发生的：

1. **练完不知道吃什么。** 食堂菜品固定，微信只能问朋友，练得认真、吃得全凭感觉。
2. **体测前不会练。** 1000 米 4 分 35、引体 3 个，网上计划要么是给体育生的，要么让你每天跑 5 公里。
3. **想运动不知道去哪、几点人少。** 兴冲冲跑到体育馆，发现全是人；或者干脆不知道学校有这么多可以拿体育积分的机会。

对应的就是三块：**配餐、积分雷达 + 体测、场馆人流**。

## 2. 产品演示（3 分 30 秒）★ 核心

### 2.1 吃：练完这顿怎么搭（1 分 45 秒）

**① 定目标（20 秒）**
- 顶部是三段式控件：**减脂 / 增肌 / 维持**，选中会填充并给一句解释——比如减脂：**「缺口约 300–500 kcal，优先保蛋白」**。
- 选「增肌」，运动选「跑步」，强度「正常」，时长拖到 **30 分钟**（数轴，分度 5 分钟）。
- 立刻算出：运动消耗 **307 千卡**、静息消耗、建议摄入、盈余/缺口 **+300**。

**② 选菜（40 秒）**
- 菜品库按 **主食 / 蛋白 / 热菜 / 蔬菜 / 汤品 / 饮品** 分组，**分类栏吸顶**，点一下直接锚定滚动。
- 顶部**搜索框**输入「鸡」，一秒筛到鸡胸、手撕鸡——不用在几十张卡里翻。
- 点几张卡勾选，分类标签上出现**「已选 N」角标**。
- 「不吃的东西」是可点的 chip，选中变成**删除线 + 灰底**。

**③ 出结果（45 秒）★**
- 点「让 Agent 配这一餐」，给出 **2–3 套横向对比卡**：每张牌上直接对比**总热量、蛋白克数、预估价格、排队时长**。
- 每套下面有一条**宏量营养条**：**蛋白 45 / 88g ｜ 碳水 63 / 98g ｜ 脂肪 17 / 20g**（本餐 / 每餐目标）。
- 再配一句人话解释：**「练后 1 小时内补快碳 + 蛋白，帮你恢复体力、长肌肉。」**
- 点「换一换」现场替换一道菜，「就吃这个」记入当餐。

> 讲一句：这套计算是**本地营养库 + MET 公式**算的，不是大模型编的，离线也能跑。

### 2.2 练：积分雷达 + 体测提分（1 分 30 秒）

**① 积分雷达（50 秒）**
- 13 个体育积分机会：参赛即得、打卡累积、课程训练、服务组织、院系日常，以及社团/民间活动（**明确标注不计分**）。
- 分类 chips + 状态分段 + 搜索，三者叠加；**未结束按截止日升序、已结束沉底**。
- 卡片是**票根章**样式：右上角砖红描边写分值。
- 点进详情：**AI 一句话摘要**（适合谁 / 不适合谁 / 分值提醒）、「我想去 / 找搭子 / 组队缺人」、讨论区、运动攻略评价。

**② 体测提分性价比榜（40 秒）★**
- 切到「体测急救站」，输入：大一男生、1000 米 **4'35"**、引体 **3 个**、12 天后体测。
- 点「算分 + 提分诊断」：1000 米约 **59 分**、引体约 **6 分**。
- 关键是这张**提分性价比榜**：按「每提升 1 个单位能加多少分」排序——
  **引体向上：再 +7 个 ≈ +54 分，性价比最高**；1000 米：再快 28 秒 ≈ +11 分。
- 现场改一个成绩，榜立刻重排——**它不是一张静态表，是会算账的教练。**

### 2.3 场馆：去哪儿练、几点去（1 分钟）

- 五个校区可切；**自绘 SVG 示意图**（不用任何地图 SDK、不涉及地图授权）。
- 每个场馆一张卡：开放时间、收费、备注、**当前人流徽章**。
- 判定是**两级兜底**，这点可以重点讲：
  1. **实时上报优先**：近 2 小时上报里超过 60% 说「人多」→ 显示人多；
  2. **没有数据就按历史规律**：20:40 下课高峰 → 人多；19:00–21:30 室内黄金档 → 人多；工作日白天 → 空闲；珠海游泳馆周一闭馆 → 直接拦。
  3. 都没有才默认「适中，欢迎上报」。
- 现在点一下「人多」，徽章立刻变——**数据只存本机，不上传**。
- 如果显示人多，卡片下面会自动给建议：**「英东现在人多，建议改去西区田径场」**。

### 2.4 教练：Agent 本体（45 秒）★

- 切到「🤖 教练」tab——这是产品的 Agent 本体，不是藏在二级菜单里的问答框。
- 先看顶部状态条：**「已连接 GLM · glm-4-flash」** 或 **「本地规则引擎（未配置 Key）」**——**没接模型就直说没接**，这是我们最在意的一条。
- 直接问：「**今晚练完腿很酸，食堂吃什么恢复快？**」→ 它会结合档案里的目标、体重回答，并给出可执行建议；每条回答下面标注是**哪个引擎生成**的。
- 点「🔥 减脂日」场景：回答立刻换成减脂口径；再点「🎯 体测前 3 天」：换成碳水加载 + 补水。**同一句话，三种场景三种答案**。
- 再点下面「练完腿酸吃什么 / 减脂怎么吃 / 引体怎么练」三个快捷问题，展示它不只是闲聊。

> 关键：Agent 不是只有一个聊天框——**配餐结果能「让教练点评这顿」、体测诊断能「让教练解读短板」、记录页的 AI 建议也真的走模型**。同一套 Agent 能力散在四个入口里。

## 3. 技术实现（50 秒）

**架构**：纯静态前端（HTML/CSS/原生 JS）→ 阿里云 ECS（Nginx 托管 + `/api` 反代 Node）→ 大模型（GLM / DeepSeek / Ollama）。

- **国内可直连**：`http://120.78.120.161/`，不用 VPN、不用备案域名，评委手机扫一下就能开。
- **确定性计算不用大模型**：热量用 MET 公式、体测用 2014 官方评分表、人流用历史规律表——**透明、可复核、零幻觉**。
- **大模型只做「解释和问答」**，输出走 JSON 校验，失败自动回退本地模板。
- **没有后端也能用**：本地规则引擎兜底，断网、没 Key 都不影响核心演示。
- **安全**：Key 只在服务器 `.env`；CORS 白名单；按 IP 限流；3000 端口不对外。

**数据**：食堂 647 道菜（五校区）、营养库 ~80 道、体测 2014 官方表（含大一/大二、大三/大四两套）、场馆五校区 22 个 + 拥挤规律表。

## 4. 创意价值 + 加分项（40 秒）

- **需求洞察奖**：三个痛点都来自身边——练完不会搭、体测不会练、去了发现人太多。
- **一键即用奖**：选目标 → 勾菜 → 出 2–3 套；30 秒输入 → 出提分榜；打开就能用，不用注册。
- **六边形战士奖**：吃、练、场馆三条线齐备，且都是**能每天用**的工具，不是一次性作品。

**社会价值**：帮同学花更少的钱吃得更合理；用「提分性价比」把有限时间花在刀刃上；把散落的校园运动机会聚合成一张雷达。

## 6. 提问预案（2 分钟）

| 可能问题 | 回答要点 |
|---|---|
| **"你们的 AI 到底在哪？"** | 四个入口：①「教练」tab 的问答与场景切换；②配餐结果「让教练点评这顿」；③体测诊断「让教练解读短板」；④记录页的运动/花销/调整建议。每条回答下面都标注了是哪个引擎生成的。 |
| **"没配 Key 还算 Agent 项目吗？"** | 不算「大模型在回答」——所以我们在界面上**明确写着「本地规则引擎」**，不把规则冒充 AI。配 Key 后自动切到模型，同一条链路、同一套 UI。 |
| **"支持哪些模型？"** | 三个：GLM（glm-4-flash）、DeepSeek（默认 deepseek-v4.1-flash）、Ollama（本地，qwen2.5 等）。`PROVIDER` 环境变量指定，或按 Key 自动选择。 |
| **"为什么算分不用大模型？"** | 评分表是教育部标准，本地算**透明、零幻觉**、可复核；模型只做解释。 |
| **"场馆人流数据哪来的？"** | 实时靠用户上报；没有上报时按《场馆拥挤度规律表》的历史规律给模拟状态，**页面上明确标注"模拟数据"**。 |
| **"学校官方有场馆系统，你们重复造轮子？"** | 官方是「预订」，我们是「去之前判断人多不多 + 该改去哪」，补的是决策这一环。 |
| **"为什么没有账号体系？"** | 比赛周期内优先保证**打开即用**；账号/云同步在路线图里，当前数据只存本机，隐私风险最低。 |
| **"积分是非官方的吧？"** | 对，页面一直标注「非官方认定，仅作个人记录」，分值以官方通知为准。 |
| **"食堂价格准吗？"** | 有标价用标价，无标价标「参考价（估）」，并支持后台手动更新。 |
| **"会不会承诺提分/包过？"** | 不会。强调科学训练与防伤，不提供医疗建议。 |
