## 0. 开场（30 秒）

各位评委老师好，我们是来自软件工程学院的团队。我们的主题词只有两个字——**运动**。

我们做的是一个面向中山大学学生的运动饮食智能体，名字叫「**练完吃啥**」，由两部分组成：

- 主项目「**练完吃啥**」：练完/没练完，走进食堂，告诉你**这顿怎么吃**；
- 副项目「**体测急救站**」：体测前两周，告诉你**先练哪项、每天练什么**。

一句话：**运动消耗的，吃回来补上；体测要考的，练起来提分。**

---

## 1. 痛点与选题（45 秒）

先说为什么做这个。我们观察身边的同学，发现两个真实的高频痛点：

**痛点一：想运动增肌/减脂，但食堂菜品是固定的，不知道怎么搭配。**
微信只能问朋友，闹钟只能提醒吃饭，都没法给专业营养建议。大家常常是"练得很认真，吃得全凭感觉"。

**痛点二：体测临近，想提分但不会练。**
比如 1000 米 4 分 35、引体向上 3 个，网上的计划不是给体育生，就是让你每天跑 5 公里。体测不是"健身"，是"在固定日期前，用有限时间多拿几分"。

所以我们的选题紧扣"运动"，但又落到**吃饭、体测**这些每天都会发生的真实场景上，**有人真的需要，有实际应用价值**。

## 2. 产品演示（3 分 30 秒）★ 核心环节

### 2.1 主项目：练完吃啥（2 分钟）

> 演示前准备：档案里填好 65kg/175cm，目标选"增肌"。

**第 1 步：今天练了什么（30 秒）**
- 点开"练完吃啥"，先选目标：**增肌**（点"💪 增肌"）。
- 运动项目选"跑步"，强度选"正常"。
- 这里请大家注意一个细节：强度不是抽象的三个字，下面有一行**判定小字**——轻松＝呼吸平稳、能说话；正常＝微喘、能短句交流；累＝大口喘气、说话费力（换算系数 0.8 / 1.0 / 1.25）。
- 把**时长**拖到 30 分钟（强调这是**数轴式拉动，分度值 5 分钟**）。
- 卡片下方立刻算出：运动消耗约 **307 千卡**（跑步 MET 9 × 65kg × 30 分钟）、静息消耗、建议摄入，以及**盈余/缺口 +300**（增肌目标）。

**第 2 步：今天食堂有什么（50 秒）**
- 这一项覆盖了**中山大学五个校区**的食堂。先选校区（南校园）→ 食堂（松涛园）→ 窗口（一楼湘菜窗口）。
- 每道菜**带价格**；没标价的菜按"自选/称重·参考价"估算，并且**支持后台手动更新**，弥补实时更新慢的缺点。
- 勾选：白米饭、水煮肉片、再来个手撕鸡。
- 把"这顿的约束"的**预算**拖到 15 元（数轴，分度值 1 元），路上时间选"不赶时间"。

**第 3 步：生成搭配（40 秒）**
- 点"🍽️ 让 Agent 配这一餐（1秒3套）"。
- 系统按 4 条策略（**蛋白优先 / 性价比 / 赶时间 / 均衡**）生成搭配，自动去掉重复的，所以通常给出 **2–3 套**；第一套用**绿框高亮**，是默认首选。
- 每套里每道菜标注**推荐/适量/少吃**，下方有蛋白质/碳水/脂肪**占比条**，以及排队/全程时间和**蛋白覆盖率**。
- 比如它会提示：水煮肉片油偏多，标注"少吃"，并给出替代——"换成清蒸鱼或白切鸡"；白米饭可以"换成玉米或杂粮饭"。点"**换一换**"现场替换一道菜，点"**就吃这个**"记入当餐。

> 讲到这里可以补一句：**这背后是本地营养库 + 规则引擎，离线也能算，不依赖网络。**

### 2.2 副项目：体测急救站（1 分 30 秒）★ 按指定人设演

> 人设：**大一男生，1000 米 4 分 35，引体 3 个，12 天后体测**。

- 切到"体测急救站"标签，30 秒输入：性别男、年级「大一」、1000 米 4'35"、引体 3 个、距体测 12 天。
- 点"🔍 算分 + 提分诊断"：
  - 系统按《国家学生体质健康标准（2014 年修订）》的**大一/大二表**算出：1000 米约 **59 分**、引体约 **6 分**；
  - 给出关键结论：**"先练引体向上"**——引体 3 个只有 6 分（几乎没拿分），练到 10 个（及格线）就是 60 分，提分空间最大。
  - 补一句：评分表内置「大一/大二」「大三/大四」**两套**，切年级会自动按对应表重算。
- 往下滚，展示**未来 12 天计划**（每天 15–25 分钟）和**引体 4 周专项训练**（退让引体 → 弹力带辅助 → 减带 → 冲标准）。
- **关键交互（让评委看到"会改"）**：在"伤病/场地限制"里填"**膝盖有点疼**"，重新诊断——下肢和跑步动作**自动换成臀桥/死虫/快走**，并说明原因。
- 再点一下**打卡调载**里的"😮‍💨 太累"：今天强度当场减半、时长砍半——它不是静态计划表。
- 最后展示**配速器**：输入目标成绩 → 每 200 米分段 → "开始报时"用 Web Audio 叮声报时，不依赖 GPS，操场和跑步机都能用。

> 收尾一句：**它不是一张静态计划表，而是会根据你的反馈实时改。**

## 3. 技术实现（1 分 30 秒）

**架构**：前端原生 HTML/CSS/JS，部署在 GitHub Pages；后端 Node.js + Express，代理调用大模型，**把 API Key 藏在后端**，前端永远看不到。

**核心设计：大模型只做"解释"，不做"计算"。**
- 体测评分表、MET 热量公式、营养库，全部是**本地确定性计算**——评分透明、不会算错；
- 大模型（GLM-4-Flash）只负责**点评、问答、教练**，输出走 JSON 校验，失败就回退本地模板。

**数据**：食堂菜单来自《中山大学食堂菜单价格明细表》647 道菜，覆盖五校区，每条标注出处；营养数据优先匹配《中国食物成分表》，搜不到就**常识估算并标注"估算值"**。

**最稳的一点**：未配置 Key 时自动降级为**本地规则引擎**，所以**离线、免费、断网都能完整演示**——这也是我们保证现场效果不翻车的关键。

## 4. 创意价值 + 加分项（1 分钟）

对照大赛的加分项，我们逐条命中：

- **需求洞察奖**：解决"学生运动后不会搭配食堂餐"和"体测不会针对性训练"两个真实高频需求；
- **一键即用奖**：选目标 → 勾菜品 → 出方案，核心任务 30 秒完成；
- **六边形战士奖**：功能、创意、体验、展示四条线齐备，并且是**可每天使用**的工具，不是一次性作品。

**社会/经济价值**：帮同学花更少的钱吃得更合理（预算约束 + 省钱建议），帮体测学生用最少时间科学提分，也传递"科学训练、防伤、长期习惯"的健康观。

---

## 5. 总结（30 秒）

回到我们的主题词"运动"——

我们用「练完吃啥」把**运动之后的饮食决策**做成了智能体，用「体测急救站」把**运动本身的提分**做成了教练。它贴近校园、每天可用、真实落地。

**运动消耗的，我们帮你吃回来；体测要考的，我们帮你练上去。** 谢谢各位评委老师！

## 6. 提问环节预案（2 分钟）

| 可能问题 | 回答要点 |
|---|---|
| **"你们的 AI 到底在哪？"** | 两层：①本地规则引擎（营养库+MET+评分表）负责确定性计算；②GLM-4-Flash 负责教练问答和点评，Key 放后端，没配置就自动降级本地，所以不联网也能跑。 |
| **"为什么算分不用大模型？"** | 评分表是教育部标准，用 JSON 本地算分**透明、零幻觉**，可复核；大模型只做解释和鼓励，出错风险最低。 |
| **"食堂价格准吗？"** | 有标价用标价；无标价按"自选/称重"参考价估算并标注"估算值"，且支持后台手动更新。这是数据源本身的局限，我们用"可更新机制"来补。 |
| **"营养数据靠谱吗？"** | 优先《中国食物成分表》匹配，搜不到才常识估算并明示"估算值"，参考文献在"原理与数据"页可查。 |
| **"会不会承诺提分/包过？"** | 不会。我们强调科学训练和防伤，明确不提供医疗建议；体测计划建议找体育老师审过，评分以学校版本为准。 |
| **"和市面上的健身 App 有什么区别？"** | 那些是"健身"，我们是"食堂场景 + 体测应试场景"的**垂直智能体**，输入的是你眼前的真实菜单和你的真实成绩，不是通用计划。 |
| **"为什么选运动这个题，不怕偏题？"** | 我们把"运动"落到两个出口：运动后的**饮食补给**和运动前的**提分训练**，饮食只是手段，核心始终是运动。 |
| **"数据安全/隐私？"** | 全部存在用户本机 localStorage，不上传服务器；API Key 只在后端。 |
| **"推荐是不是只按我勾的菜来？"** | 推荐从你当前选的**校区→食堂→窗口**的菜里，按 4 条策略搭 2–3 套；勾选用于**本餐摄入参考与记录**。每套都能"换一换"，也能"就吃这个"记入当餐。 |
| **"能让所有人随时用上 AI 吗？"** | 能，但卡在入口：现在后端在 Vercel（海外，国内被墙）。下一步换**国内云函数/自定义域名**即可，Key 始终只在后端——路线见 `docs/完善路线.md`。 |
