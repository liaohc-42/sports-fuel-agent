# 后续完善路线（Roadmap）

> 当前版本已覆盖题目要求全部功能。以下按「投入产出比」排序，供后续迭代。

## 短期（答辩后 1–2 周，性价比最高）

1. **食堂数据自动更新**
   - 目前 647 道菜中约 16% 有标价，其余为"自选/称重·参考价"。
   - 建议：做一个极简的**后台录入页**（填校区/食堂/窗口/菜名/价格），数据存后端或直接生成新的 `canteen.js`；或与学校食堂窗口对接当日菜单。
   - 已有基础：`POST /api/canteen` 手动更新接口 + `scripts/xlsx_to_canteen.py` 重新生成。

2. **菜品图片一键输入**
   - 目标卡片需求："菜单图片一键输入"。可用浏览器 OCR（如 Tesseract.js / 腾讯云 OCR）识别食堂窗口照片，自动转成可勾选列表，再走现有流程。

3. **更细的运动记录**
   - 目前"最近运动"的直方图数据来自本地记录；可在"练完吃啥"生成搭配时**自动把当次运动写入日志**，让直方图与热量缺口联动。

## 中期（1 个月）

4. **大模型"联网检索"增强**
   - 目前营养检索 = 本地库优先 + LLM 常识估算。可接 GLM 的 **web-search 工具**（或 Function Calling），对未收录菜品实时检索营养数据，检索不到再估算并标注"估算值"。
   - 输出统一走 JSON Schema + 规则校验，失败回退本地。

5. **分享卡 / 班级榜（体测急救站可选功能）**
   - 生成一张"今日搭配 + 训练"的图片分享卡；体测成绩做匿名班级榜（注意隐私，可做成"自愿公开"）。

6. **多端/离线安装**
   - 加 PWA（manifest + service worker），可"添加到主屏幕"，弱网/断网可用。

## 长期

7. **Cloudflare Worker 版后端**
   - `api/agent.js` 的 `callGLM` 已是标准 fetch，可平移到 Worker：写一个 `fetch` handler，读环境变量 `GLM_API_KEY`，转发到智谱 API。比 Vercel 更省（免费额度更大）。

8. **数据仪表盘与提醒**
   - 把"记录"页做成周报（摄入 vs 消耗趋势、花销趋势）；到点提醒"练后补充""体测倒计时"。

9. **安全与多用户**
   - 后端加用户鉴权（体测成绩、花销属个人数据）；数据可同步到云端（当前仅 localStorage）。

## 附：让「所有人」都用上 AI —— 后端入口方案

> 现状：后端在 Vercel（`sports-fuel-agent-backend.vercel.app`），**国内直连被墙**（实测 TCP 超时）。
> 注意：配餐、热量、体测评分全部走**本地引擎**，后端只影响「AI 点评 / 教练问答 / 图片识别」，所以后端不可用不影响核心演示。

| 方案 | 国内直连 | 成本 | 改动量 | 备注 |
|---|---|---|---|---|
| Vercel（现状） | ❌ 被墙 | 免费 | 0 | 只剩海外 / 开代理可用 |
| **阿里云函数计算 FC** | ✅ 默认域名 | 免费额度 | 小 | **推荐** |
| 腾讯云 SCF + API 网关 | ✅ | 免费额度 | 小 | 同类可选 |
| 云服务器（学生机） | ✅（IP 直连） | ~10 元/月 | 0 | `npm start` 即可，最省事 |
| Cloudflare Workers | ⚠️ 不稳定 | 免费 | 中 | 不建议当国内主入口 |
| 内网穿透（frp/ngrok） | ⚠️ 临时 | 免费/低 | 0 | 只适合答辩现场兜底 |

### 落地步骤（以阿里云 FC 为例）

`backend/server.js` 已经 `module.exports = app`，所以直接包一层就行：

```js
// backend/index.js
const serverless = require('serverless-http');
const app = require('./server');
module.exports.handler = serverless(app);
```

1. FC 控制台新建 Node.js 18 函数，触发器选 **HTTP**；
2. 上传 `backend/`（连同依赖）或在线安装依赖；
3. 环境变量填 `GLM_API_KEY=...`、`PROVIDER=glm`（DeepSeek 同理换 `DEEPSEEK_API_KEY`）；
4. 拿到默认域名（形如 `https://xxx.cn-hangzhou.fcapp.run`），加到 `frontend/js/api.js` 的 `API_BASES` **第一位**（代码已支持多后端顺序尝试，无需改逻辑）；
5. 访问 `https://<新域名>/api/health`，看到 `provider: "glm"` 即成功，再跑一遍 `_verify_live.js`。

### 公开后端必做三件事

- **CORS 白名单**：只放行 `https://liaohc-42.github.io`，别留 `app.use(cors())` 全放行；
- **限流**：按 IP 每分钟 10 次左右、请求体 ≤100KB（现在是 1mb）；
- **预算**：给 Key 设用量上限与告警，防止被刷爆（公开 Key 等于公开钱包）。

> 结论：**比赛演示不依赖公网后端**（本地引擎足够）；「所有人随时可用」属于赛后项，优先 FC / SCF。
