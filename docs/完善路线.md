# 后续完善路线（Roadmap）

> 当前版本已覆盖题目要求全部功能。以下按「投入产出比」排序，供后续迭代。

## 短期（答辩后 1–2 周，性价比最高）

1. **食堂数据自动更新**
   - 目前 647 道菜中约 16% 有标价，其余为"自选/称重·参考价"。
   - 建议：做一个极简的**后台录入页**（填校区/食堂/窗口/菜名/价格），数据存后端或直接生成新的 `canteen.js`；或与学校食堂窗口对接当日菜单。
   - 已有基础：`POST /api/canteen` 手动更新接口 + `scripts/xlsx_to_canteen.py` 重新生成。

2. **菜品图片一键输入**
   - 目标卡片需求："菜单图片一键输入"。可用浏览器 OCR（如 Tesseract.js / 腾讯云 OCR）识别食堂窗口照片，自动转成可勾选列表，再走现有流程。

3. **更细的运动记录**
   - 目前"最近运动"的直方图数据来自本地记录；可在"练完吃啥"生成搭配时**自动把当次运动写入日志**，让直方图与热量缺口联动。

## 中期（1 个月）

4. **大模型"联网检索"增强**
   - 目前营养检索 = 本地库优先 + LLM 常识估算。可接 GLM 的 **web-search 工具**（或 Function Calling），对未收录菜品实时检索营养数据，检索不到再估算并标注"估算值"。
   - 输出统一走 JSON Schema + 规则校验，失败回退本地。

5. **分享卡 / 班级榜（体测急救站可选功能）**
   - 生成一张"今日搭配 + 训练"的图片分享卡；体测成绩做匿名班级榜（注意隐私，可做成"自愿公开"）。

6. **多端/离线安装**
   - 加 PWA（manifest + service worker），可"添加到主屏幕"，弱网/断网可用。

## 长期

7. **Cloudflare Worker 版后端**
   - `api/agent.js` 的 `callGLM` 已是标准 fetch，可平移到 Worker：写一个 `fetch` handler，读环境变量 `GLM_API_KEY`，转发到智谱 API。比 Vercel 更省（免费额度更大）。

8. **数据仪表盘与提醒**
   - 把"记录"页做成周报（摄入 vs 消耗趋势、花销趋势）；到点提醒"练后补充""体测倒计时"。

9. **安全与多用户**
   - 后端加用户鉴权（体测成绩、花销属个人数据）；数据可同步到云端（当前仅 localStorage）。

## 始终遵守的红线

- 不承诺"包过/提分"；涉及伤病建议就医；体测评分以学校执行版本为准。
- 强调科学训练、防伤、长期习惯，避免"应试投机"观感。
